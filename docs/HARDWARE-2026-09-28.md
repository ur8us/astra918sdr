# Astra918 hardware check, 28 September 2026

The connected RP2350 (`c0de:091a`) and Pico Debugprobe (`2e8a:000c`) were
accessible. Before programming, both 4 KiB flash settings sectors were backed
up. Each held a valid version 1 record (sequences 14 and 15). `probe-rs`
programmed and verified the RP235XA ELF without a chip erase; the settings
sectors compared byte-for-byte with the backup after flashing. The debug tool
reported a core lockup during each download/reset transition, but USB
reenumerated and the receiver answered control requests afterward.

The firmware loaded the old settings with Internal reference and all logical
GPIO values clear. GPIO0 and GPIO7 updates changed the status bits and revision
without changing the I/Q generation. An explicit Save wrote a valid version 2
record; after reset, the GPIO values were retained. They were then cleared
and saved. No physical RP2350 pins were assigned.

Selecting External with no external oscillator connected returned control
status 8 and left `configured=false` with External shown as the requested
source. Switching back to Internal recovered the receiver directly and cleared
the fault. One state-commit bug found by this test was fixed before the final
flash. The final receiver is configured, error 0, Internal, GPIO mask 0,
10.136 MHz, and saved revision equals current revision.

With the high-band manual L=4 path, 132 MHz configured and locked. Requests for
140 MHz and 170 MHz returned status 8 with a PLL timeout; the receiver was
restored to 10.136 MHz and saved. These checks establish only chip lock and
control behavior, not RF calibration or reception at those frequencies. No
frequency generator was used.

The firmware was later changed to use manual L-divider settings above the
normal range. That change was made after these measurements and has not been
flashed or hardware checked yet.

GNU Radio 3.10 received 241,635 complex samples over two seconds through the
vendor USB interface. A separate run of its message control block retuned the
spectrum center by 1 kHz and restored it while receiving samples; GPIO0 was
also set and cleared. The SDR Console Linux bridge was stopped temporarily to
release vendor interface 4 and restarted afterward. Its rebuilt Linux helper
and Wine source DLL were installed and the bridge service and receiver status
were checked. Native Windows and macOS hardware checks were not run.
